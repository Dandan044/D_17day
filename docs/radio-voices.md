配套约束：

- **单个事件 1–10 轮**，轮数呈正态分布：1-2 轮约 20%、3-6 轮约 60%、8-10 轮约 20%。
  8-10 轮只给关键事件与重大转折。
- **每一轮都必须有对话选项**（2026-09-15 起收紧：不允许任何"单方面发消息"的轮次——
  包括后果轮。收尾轮的选项是玩家的收尾动作，如「把电台关小」「守着听完」，不是摆设）。
- 每个含选项的轮次含一个**「什么都不回应」**：不按键、不发送、不发射。
  选定后本事件当场收束（引擎层"过夜自动选定"尚未实现，见框架核查）。
- **不写金句收束**。规则全文见 [content-voice.md](content-voice.md)。

## 模范线规范（后续频道照这 8 条验收）

1. **一个事件 = 一件事。** 有开场、有玩家的位置、有后果落地。禁止纯播报事件——
   收尾轮也必须给玩家收尾动作选项，不许"她说完就没了"。
2. **事件不属于日期，属于池子。** 事件声明 `stage:[min,max]`（threat 1-6 阶段区间）
   与 `minBond`（好感档下限 1-4），由引擎三优先级抽签（关联关键 → 关键 → 普通池随机）
   决定今天谁到场。**沉默也是内容**：池空或门槛全不过 = 今天这一头没有消息。
3. **选项三直值。** 对话只直接影响三样：**好感**（数值不可见、选择前不可预知——note
   禁止暗示好感后果）、**理智**（视剧情悲喜）、**电量**（`kwh` 字段，note 用 `{kwh}`
   占位明示，蓄电不足时选项禁用）。好感与理智的增减由内容声明，UI 不显示数值。
4. **其余后果走两条间接途径。** ① `Effect.enqueue`：对话结束后向今日待办**直接插入**
   事件家族（绕过每日上限，queue 挡睡觉＝今日必须处理）；② 解锁一次性外出地点
   （`Effect.locations` + `schedule waitFor:'scavenge'` + `visited:*` 标签），前往后触发
   剧情事件。**禁止**在对话选项里直接给物资、改状态。
5. **生死由行为链决定，不由暗数值决定。** 轮级 `minAffinity` 不得用于死亡判定；
   事件级 `minBond/minAffinity` 只表达"对方的行为逻辑"（她只向信任的人求救），
   失败路径必须有内容（静默或"来晚了"），不许静默失败。死亡呈现为事实，不呈现为惩罚。
6. **正文无旁白（2026-09-15 收紧）。** 对话型文案里禁止一切叙述层——她那头的动静、停顿多久、
   谁没说话，全部不写。要么进台词（她主动说出口），要么不写；停顿的呈现是引擎与 UI 的事。
   生成用场景卡（第 N 天实情、她家状态）仅作 LLM 参考，标注「不进正文」。
   旧的「narrate 只写电波能传达的」条款废止——本轮起正文只有对话行。
7. **语言指纹先行。** 动笔前先读对应设定集（xt-bible.md）。阶段改变语言：
   匮乏期她摊开生活；掠夺期只问门；严冬期第一次开口要；荒芜期不问了；死寂期谈"以后"。
8. **flag 极简。** 只写有下游消费者的 flag。当前线内：`flag:xtKnowsAddress`（得知门牌）、
   `flag:xtAlive`（营救成功）、`flag:xtGone`（失败路径）、`flag:xtMomGone`（母亲结局）等，
   以 xt-pool.md 的事件表为准；新增 flag 必须在这份蓝图里登记用途。

## 框架核查（引擎 `engine/channels.ts` 现状，2026-09-15 二次重构后）

1. **固定日到场：已废除。** `at`/`afterDays`/`keepWaiting`/`elseEvent` 字段与
   `eventDue`/`resolveElseEvent` 已删除。事件按池抽取，见 `pickEvent()` 注释
   （三优先级：关联关键 → 最早未完成 key → 普通池 `derivedRng.pick`；池空 = 今天无消息）。
2. **抽签的随机性**：只用 `derivedRng(run)`（rng.ts，与共享 RNG 游标完全隔离，
   sim 基线不漂移）。`enqueue` 选变体同样走 derivedRng。
3. **多轮选项**：家族事件（EventCard）的 `Choice` 现在支持 `next`（同家族变体 id），
   `resolveChoice` 不出队、改写 `queue.variantId`，两套皮肤自动翻页；
   `emitHook('choice')` 与 `recordBeat` 只在链末发射。
4. **电量门槛**：`ChatChoice.kwh`，`replyChannel`/`hailChannel` 闸（不足 →
   `channels.err.noPower`），`registerSend` 兑现扣减；UI note `{kwh}` 插值 + 禁选。
5. **「什么都不回应」的过夜自动选定**：引擎层仍未实现（超时走通用收场）。
   若要补齐：`ChatChoice` 加 `defaultQuiet`，超时分支自动执行，约 15 行，动前过目。
6. **事件进行中日历不插手**、`replyWindowDays` 超时、频道信箱/静默机制：全部保留。
7. **长对话尾轮的特殊事件接口**：8-10 轮事件的尾轮挂 `enqueue`/解锁地点，
   具体规则等用户提供后在 `xt_c_rescue`、`xt_f_end`、`xt_f_epilogue` 三处落地。
