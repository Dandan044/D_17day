# 七日之前 / SEVEN DAYS BEFORE

末世准备与生存的文字经营 roguelite。纯前端，无后端，跑在浏览器里。

单局 49 天：**7 天备灾 + 42 天求生**，约 25-40 分钟。

## 运行

```bash
npm install
npm run dev          # 开发服务器，默认 http://localhost:5180
npm run build        # 类型检查 + 生产构建
npm run lint:content # 内容一致性校验（见下）
npm run sim -- 240   # 无头模拟 240 局，输出平衡报告
```

## 玩法结构

```
Day 1        选址（6 个站点，决定你能建什么、会遇到什么）
Day 1-7      准备期：采购、搜集、施工、分析情报
             每天 3 条真假混杂的情报，你要赌出七天后来的是哪种灾难
Day 8        崩溃日：灾难揭晓 + 准备度清算，押对的和押错的都在这一刻兑现
Day 8-49     生存期：每天晨报 → 分配行动点 → 事件抉择 → 夜间结算
             每 7 天末世等级 +1（恐慌 → 匮乏 → 掠夺 → 严冬 → 荒芜 → 死寂）
Day 49       结局判定 → 遗物结算 → 局外解锁
```

## 三个核心张力

**情报真伪。** 灾难类型（核交火 / 超级流感 / 电网崩溃 / 火山冬天 / 区域洪灾 / 化工泄漏）开局随机且隐藏。一条情报的真伪不由内容作者指定，而由运行时决定：它指向的灾难 == 本局真实灾难则为真。同一条「化工园区起火」的推文，在化工局是救命线索，在核战局就是噪音。押错方向不必死，但会明显吃紧。

**暴露度。** 一条累积的热度条，不是单日噪音判定。连开三晚发电机会先招来「有人在盯着这里」，你不处理，两天后才是武装突袭。袭击因此有铺垫。

**配给与用电。** 每天要定口粮档位、用水档位和夜间用电策略。全负荷舒适但暴露，全黑省油隐蔽但掉士气。饿肚子省下的粮食就是多活的天数。

## 避难所：三条建造路径

同一个模块升级有三种达成方式，构成「时间 vs 金钱 vs 风险」的三角：

- **DIY** — 建材 + 零件 + 工时（进队列，跨天）。技能不足有失败率。
- **雇工** — 大量现金 + 1 AP，两天完工。**崩溃日后这条路直接关闭**。
- **买成品** — 现金 + 1-3 天物流延迟，且有概率钱付了货到不了。买得早又便宜又能到。
- **拆解回收**（崩溃后解锁）— 拆家具、拆车、撬邻居空房。产生噪音，撬邻居家掉人性。

关键机制：**施工中的模块处于劣化状态**。加固施工到一半时门窗是拆开的，防御比不动工更低。所以「什么时候动工」本身是一个抉择。

### 事件系统：家族与变体

事件不看「第几天」，而是看**当前世界的标签集合**。世界状态持续演化，标签由状态实时推导，事件按标签匹配。

一个 `EventFamily` 下挂多个 `variant`。引擎先按权重选家族，再按标签选出唯一合理的变体。所以「有人来抢你」只写一次：

- 洪灾局 → 有人划着橡皮艇撬你二楼的窗户
- 核战局 → 巡逻队以战时征收的名义清点物资，留下一张白条
- 地下站点 → 有人在通风井上方喊话，威胁往里灌汽油
- 暴风雪 → 一群冻僵的人堵在门口，他们不像是来抢的，但也没打算走

因果链靠 `effect.schedule` 往未来种事件：拒绝给邻居水，一周后邻居不再替你预警；给民兵交了保护费，暴徒少了但政府军线里你被标记成通敌。

### 为什么要有 lint:content

「洪水时不能有人踹门」这类约束靠人记是不可持续的。`npm run lint:content` 把它变成能报错的东西：

- 每个标签必须在 `tags.ts` 注册表里（拼错会让过滤器静默失效）
- `schedule` 指向的事件家族必须存在（否则因果链断掉）
- 每个（灾难 × 末世等级 × 天气）组合下的可用事件数不能低于阈值
- 互斥标签被同时 require 的事件永远不会触发
- `baseWeight` 为 0 且没人 schedule 的家族是死内容
- 暴露度阶梯的每一档必须在所有（灾难 × 站点 × 天气）组合下都有可用变体

它在开发中已经抓到过真问题：化工泄漏局下「勒索」这一档曾经完全没有可用变体，导致暴露度爆表却什么都不会发生；还有一个事件的所有选项都带前置条件，玩家可能在没钱没物资时被卡死。

### 为什么要有 sim

`npm run sim -- 240` 用一个"及格水平的玩家"策略跑几百局，报告通关率、平均存活天数、按灾难与按站点的分布、以及死因构成。它有两个用途：

1. **抓运行时错误** —— 几百局里任何一次崩溃都会被记录下来，比手点快得多。
2. **看平衡** —— 当前基线：及格策略约 30% 通关、平均存活 38.5/49 天，灾难间难度差距约 1.5 倍。死因以饿死为主（32%），这是经营游戏应有的主要压力。

机器人在灾难揭晓后会按灾难的关键模块重排建造顺序。开启这条策略让通关率从 25% 升到 30%，核战局从 8.6% 升到 20%——这个差值就是「猜对灾难」这个机制的实际收益。

## 添加内容

加一个事件：在 `src/game/content/events/` 下往对应数组里追加一个 `EventFamily`，然后跑 `npm run lint:content`。

加一个站点：往 `src/game/content/sites.ts` 追加，注意 `tags` 会直接进入事件过滤器，`caps` 决定各模块上限。

调平衡：只改 `src/game/balance.ts`。
